# 문장 작성 규칙

## 원칙

- 사용자가 해야 할 행동을 동사로 쓴다.
- 한 문장에는 하나의 의미만 담는다.
- 서버·애플리케이션보다 사용자를 주어로 쓴다.
- 같은 기능은 문서·화면·API에서 같은 용어를 사용한다.
- 에러 코드나 개발 용어를 그대로 노출하지 않는다.
- 버튼은 결과가 분명한 동사로 작성한다. 예: `신청하기`, `다시 시도`.

## 상태별 문구

| 상황          | 나쁜 예          | 좋은 예                                     |
| ------------- | ---------------- | ------------------------------------------- |
| 입력 오류     | Validation Error | 비밀번호를 8자 이상 입력해 주세요.          |
| 인증 실패     | 401 Unauthorized | 로그인 정보가 올바르지 않아요.              |
| 권한 없음     | Forbidden        | 이 기능을 사용할 권한이 없어요.             |
| 네트워크 오류 | Network Error    | 인터넷 연결을 확인한 뒤 다시 시도해 주세요. |
| 빈 목록       | No Data          | 아직 등록된 외출증이 없어요.                |

## 리뷰 체크

- [ ] 누구에게 보여주는 문장인지 명확한가?
- [ ] 사용자가 다음에 할 행동을 알 수 있는가?
- [ ] 기술 용어 대신 이해하기 쉬운 말인가?
- [ ] 존댓말과 문장 끝맺음이 일관적인가?
