# 커밋 규칙

## 형식

```text
type: 한글 설명 (#이슈번호)
```

## 타입

| 타입       | 의미           |
| ---------- | -------------- |
| `feat`     | 새 기능        |
| `fix`      | 버그 수정      |
| `ui`       | UI 변경        |
| `refactor` | 구조 개선      |
| `chore`    | 설정·관리 작업 |
| `test`     | 테스트         |
| `docs`     | 문서           |

예시:

```text
feat: 로그인 화면 구현 (#3)
chore: pnpm 설정 추가 (#2)
docs: 외출증 API 문서 작성 (#5)
```

## 커밋 분리 기준

- 의존성·도구 설정과 기능 구현을 분리한다.
- 폴더 구조 추가와 실제 기능 구현을 분리한다.
- 문서 변경은 관련 기능 커밋과 분리한다.
- 포맷 자동 수정만 있는 경우 `style` 타입을 사용해도 된다.
- 커밋 전 `git diff --staged`로 의도하지 않은 파일이 포함되지 않았는지 확인한다.

## 함수 작성 규칙

- 프로젝트의 함수는 화살표 함수로 작성한다.
- React 컴포넌트, API 함수, 이벤트 핸들러, 유틸리티 함수에 동일하게 적용한다.
- 함수 타입은 매개변수와 반환 타입을 명확하게 작성하고, 반환값이 없으면 `void`를 사용한다.

## 작업 예시

```text
chore: Axios와 Zustand 의존성 추가 (#12)
chore: 외출증 페이지 구조 추가 (#12)
feat: 외출증 신청 폼 구현 (#12)
test: 외출증 신청 상태 검증 추가 (#12)
docs: 외출증 최종 개발 보고서 작성 (#12)
```
