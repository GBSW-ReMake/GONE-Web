# 역할과 권한

## 역할

| 역할         | 의미   | 웹에서 확인할 기능 예시                |
| ------------ | ------ | -------------------------------------- |
| `STUDENT`    | 학생   | 본인 정보, 외출 신청, 급식·시간표 조회 |
| `TEACHER`    | 교사   | 학생 조회, 외출 승인·거절 등           |
| `DISCIPLINE` | 선도부 | 담당 관리 기능                         |
| `ADMIN`      | 관리자 | 시스템 관리 기능                       |

실제 역할 이름과 역할별 API 권한은 GONE Server 명세를 최우선으로 한다.

## 권한 처리 위치

1. **라우트**: 접근할 수 없는 페이지 진입을 막는다.
2. **메뉴**: 사용할 수 없는 메뉴를 노출하지 않는다.
3. **버튼**: 현재 상태·역할에 따라 행동을 비활성화한다.
4. **서버 응답**: 최종 권한 판단은 401·403으로 확정한다.

## 원칙

- 프론트에서 숨긴다고 보안이 보장되는 것은 아니다.
- 학생 화면에 교사·선도부·관리자 기능을 노출하지 않는다.
- 401은 인증 만료·실패, 403은 로그인했지만 권한 없음으로 처리한다.
- 역할에 따라 같은 API의 화면 문구나 행동이 달라지면 계획서에 기록한다.
- 권한으로 숨긴 기능은 키보드 탐색에서도 접근되지 않아야 한다.

## 권한 확인 체크리스트

- [ ] 로그인하지 않은 사용자의 접근 처리
- [ ] 역할별 라우트 접근 처리
- [ ] 역할별 메뉴 노출 처리
- [ ] 버튼 및 변경 행동의 권한 처리
- [ ] API 403 응답 처리
- [ ] 직접 URL 입력으로 접근하는 경우 처리
