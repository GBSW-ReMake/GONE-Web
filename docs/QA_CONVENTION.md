# QA 규칙

## 기능별 필수 확인

| 상태      | 확인 내용                                                   |
| --------- | ----------------------------------------------------------- |
| 정상      | 올바른 입력과 응답으로 목표 행동 완료                       |
| 로딩      | 중복 제출 방지, 로딩 표시, 레이아웃 흔들림 확인             |
| 빈 상태   | 데이터가 없을 때 안내와 다음 행동 제공                      |
| 오류      | API 실패·네트워크 끊김·잘못된 입력 안내                     |
| 권한 거부 | 403과 직접 URL 접근을 처리                                  |
| 인증 만료 | 401 재발급, 실패 시 로그인 이동                             |
| 반응형    | 모바일·태블릿·데스크톱 레이아웃 확인                        |
| 접근성    | 키보드, 포커스, 라벨, 대비 확인                             |
| 모션      | 고정 배치, 느린 폼 상승 전환, reduced-motion, 직접 URL 확인 |

## 백엔드 미연동 기능

백엔드가 준비되지 않은 기능은 Mock API로 먼저 검증할 수 있다. 단, Mock 테스트와 실제 API 테스트를 같은 것으로 취급하지 않는다.

### Mock 테스트

- 실제 API와 동일한 Method·Endpoint·Request·Response를 사용한다.
- 정상·로딩·빈·입력 오류·서버 오류·401·403 응답을 고정 Fixture로 재현한다.
- 중복 제출, 재시도, 토큰 삭제, 라우트 이동을 확인한다.
- 사용자 노출 오류가 한국어인지 확인하고 영어 오류 문자열·스택 트레이스가 화면에 나타나지 않는지 확인한다.
- 화면 전환 모션이 끝나기 전에도 링크·입력·키보드 사용이 막히지 않는지 확인한다.
- `prefers-reduced-motion: reduce`에서 모션 없이 로그인·회원가입 화면이 정상 사용되는지 확인한다.
- 화면 스타일이 TSX Tailwind `className`으로 적용되고 `App.css` 의존성이 남아 있지 않은지 확인한다.
- 테스트 브랜치·커밋·`NEXT_PUBLIC_API_MODE=mock`를 기록한다.
- Next.js 전환 전의 기록은 기존 Vite 실행값을 과거 이력으로 남기고, 현재 검증은 `NEXT_PUBLIC_API_MODE=mock`으로 기록한다.

### 오류 발견 즉시 기록 규칙

- 빌드 실패, TypeScript 오류, ESLint 오류·경고, 브라우저 콘솔 오류, 화면 동작 불일치는 모두 QA 이슈로 기록한다.
- `.next` 캐시·생성 파일·환경 설정처럼 제품 코드가 직접 원인이 아닌 경우에도 개발·QA를 막았다면 기록한다.
- **수정 전에** `docs/fe/issues/issue-{번호}-{기능명}-{설명}.md`를 새로 만들거나 기존 기능 QA 문서에 증상을 기록한다.
- 기록 순서는 `발견 환경 → 재현 방법 → 예상·실제 결과 → 원인 → 수정 → 동일 절차 재검증`이다.
- 이슈 문서가 해결 결과로 갱신되기 전에는 해당 오류를 해결 완료로 체크하거나 커밋·Push하지 않는다.
- 인증 마무리 QA에서는 역할별 자동 이동, 보호 라우트 직접 접근, 로그아웃 시 토큰 삭제, 인증번호 30초 쿨다운과 5분 만료를 별도 확인한다.

### 실제 API 테스트

- 백엔드 연결 후 같은 시나리오를 다시 실행한다.
- 테스트 계정 역할과 서버 환경을 기록한다.
- Mock과 실제 응답의 필드·상태 코드·문구가 다르면 API 계약 차이로 보고한다.
- 실제 API를 확인하지 못한 항목은 완료가 아니라 `미검증`으로 표시한다.

## QA 기록 항목

- 테스트한 브랜치와 커밋
- 브라우저·운영체제·화면 크기
- 테스트 계정 역할
- 재현 절차와 실제 결과
- 스크린샷·영상·콘솔·Network 증빙
- 발견 이슈의 심각도와 재검증 결과

## 심각도

| 심각도   | 기준                                    | 처리                 |
| -------- | --------------------------------------- | -------------------- |
| Critical | 로그인 불가, 데이터 손실, 보안 문제     | PR 전 반드시 수정    |
| Major    | 핵심 기능 사용 불가, 잘못된 데이터 표시 | 담당자 검토 후 수정  |
| Minor    | 일부 화면·문구·간격 문제                | 우선순위에 따라 수정 |

## 로컬 검증

```bash
pnpm lint
pnpm format:check
pnpm build
```

모든 기능 PR에는 정상·로딩·빈·오류·권한 상태의 확인 결과를 남긴다.
